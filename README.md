# All in All Exam Practice

Timed CBSE practice papers, generated in the browser and marked instantly.

- Mathematics, English, Hindi, Computer Science: Classes I to XII
- EVS: Classes I to V
- Science, Social Science: Classes VI to X
- Physics, Chemistry, Biology, Accountancy, Business Studies, Economics, History, Geography, Political Science: Classes XI and XII

Live site: https://my-exam.in

## Hosting
- Hosted on GitHub Pages from the `main` branch (root folder).
- `CNAME` sets the custom domain `my-exam.in`.
- The app is one static page (`index.html`) with no build step. School question banks are in `school-questions/` and official exam papers in `jee/`, `jee-adv/` and `neet/`; both load only when a paper needs them.

## Editing a question bank
1. Edit the subject's file in `school-questions/` (for example `school-questions/physics.json`).
2. Run `py tools/build_school_index.py` from the site folder. It updates the bank index in `index.html` (chapters and question counts) and the list of bank files in `sw.js` (the service worker saves each bank the first time it is used, and drops the old copy of an updated bank).
3. Run `py tools/build_pages.py`. It rebuilds the pages for search engines and `sitemap.xml`. Do not edit the pages it makes by hand.
4. Run the tests (below) and upload the changed files together.

## Pages for search engines
`py tools/build_pages.py` makes:
- `cbse/`: one page per class and subject, with chapters and sample questions.
- One page per chapter for Class 9 Science and Mathematics, Class 10 Science, Social Science, English and Mathematics, and Class 11 and 12 Physics, Chemistry, Biology and Mathematics (`CH_SCOPE` in the tool), such as `cbse/class-12/physics/current-electricity/`, with sample questions and answers. A chapter gets a page once it has 15 questions. Hindi chapters, in every class, get a page from 10 questions (showing 5 samples below 15), at an address spelt in plain Latin letters from the Devanagari name (`cbse/class-8/hindi/malhar-nae-mehaman/`); the tool checks that no two chapters share an address. Mathematics questions are generated by the app, so their samples come from `tools/maths-samples.json`; run `powershell -File tools\make-maths-samples.ps1` to remake it after changing the Mathematics generators, then run `build_pages.py`.
- One page per official paper, such as `jee-main/2026-2-april-shift-1/`: the pattern, subject-wise marks, chapter-wise weightage, a few solved questions and the full answer key.
- Chapter-wise past questions for each exam: `neet/chemistry/` lists the chapters tagged in the NEET papers, most-tested first, and `neet/chemistry/<chapter>/` has every question on that chapter from all the papers, with answers, solutions and a button that opens it in the app. A chapter name in both Class 11 and Class 12 (Probability, Relations and Functions) gets the class in its address, such as `probability-class-12/`. Link each new exam subject page from the exam's own page (the tests check it).

It also writes `EXAM_CH` in `index.html`: the chapters tagged in each exam's papers, used by **Practise by chapter** on each exam screen (every question on one chapter from all that exam's papers). The tests check that it matches the papers, so run the tool after any change to a `paper.json`.

After adding a paper's figures, run `py tools/optimise_figures.py` (needs Pillow: `py -m pip install pillow`). It re-compresses every paper figure and keeps a smaller file only if it has exactly the same pixels, so it never changes how a figure looks.

After adding an official paper (its `paper.json` and its entry in `EXAM_PAGES` in `index.html`), run the tool and add a link to the new paper page under the papers list on its exam page (`jee-main/index.html`, `jee-advanced/index.html` or `neet/index.html`). The tests check that the link exists.

## Tests
- `powershell -File tests\run-tests.ps1` runs `tests/marking.html`, `tests/journey.html` and `tests/offline.html` in headless Microsoft Edge (needs Python and Edge) and prints PASS or the failed checks.
- `tests/offline.html` installs the service worker and checks what it saves: the pages at install, each question bank only when it is first used, and exam papers from the network.
- `tests/journey.html` drives the app at phone (390 px) and desktop (1200 px) width as a student would: the home page, a school paper (answer, flag, navigator, Review blank, resume after closing, results, Your next step, retries), practice mode, a class challenge (the link gives the same questions every time; its code goes into the results and the score message; an edited code is ignored), a JEE Main paper and, at phone width, every official paper.
- The tests cover reading typed numbers, checking answers, the marking rules (+4 / −1, numerical ranges, dropped questions, JEE Advanced partial marks, school part marks), option labels in My mistakes, every official paper (question count, maximum marks, answer keys), every school bank (counts match the index, every answer key is accepted), every Mathematics generator (runs 40 times with a fixed seed: no errors, every key accepted when typed, every multiple-choice version has 4 different options) and the pages for search engines (every class, subject and paper has a page, and every paper page's answer key matches the marking).
- GitHub runs the same tests on every push (`.github/workflows/tests.yml`, on a Windows runner). The result shows as a tick or a red cross on the commit; the Actions tab has the log with any failed checks.
- You can also open `tests/marking.html` in a browser from any local web server.

## Progress backups
"Save a backup" on the progress card downloads `my-exam-progress-<date>.json`: `{"app":"my-exam.in","v":1,"saved":<ISO time>,"data":{...}}`, where `data` holds the browser storage entries `aa-history` (papers), `aa-days` (streak dates), `aa-mistakes` (My mistakes; each record's `due` is when it next comes back for revision and `st` is 1 once it has been answered right once), `mpp-settings`, `aa-want` and `aa-want-papers`, each as the JSON string the app stores. "Restore a backup" merges a file into what is already on the device and never removes anything. A backup file can be edited by hand, so restoring trusts nothing in it: paper records are rebuilt from known fields with type and range checks, a saved question is kept only if its HTML uses the tags and attributes the site itself produces (images only from the site's own folders, no links, scripts, event handlers or `url()`), and settings must be plain values. If the format changes, raise `v` and keep reading older versions.
- `tests/render-check.html` (open it from a local web server) renders every question, option and solution of every official paper with KaTeX and lists any maths that fails to render and any figure that fails to load. Run it after adding a paper.
